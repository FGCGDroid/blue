# 4.0 立项评估（未立项）

> 状态：只立 charter，不写代码，不排期  
> 结论：现在不做 4.0，先把 3.0 做到能实战  
> 顺序：3.0 先发布 → 4.0 后开发 → 4.0 长线测试
>
> 详见 [`sequencing.md`](sequencing.md)
> 复评：2028-Q1，3.1.0 发布并稳定后

## 为什么现在不做

代码速度确实够，但 3.0 还没到“能实战”：

```text
73 个工具还没迁完
12 页签控制台还没重写
影子双跑还没做
K1–K5 只有测试证据，没有真实靶场/上游证据
3.0.0 还没发布
```

现在开 4.0，只会得到：

```text
更多目录
更多版本号
更多没验证的“能力”
```

这就是版本号通胀，不是进步。

## 4.0 不是 3.0 的放大版

4.0 必须是**新的能力类别**，能独立验证，不是：

```text
3.0 + 更多工具
3.0 + 更多页签
3.0 + 更漂亮的 UI
```

候选主题（最终只选一个主主题）：

```text
A  多主机 / 多目标持续防守
   从单机网关扩展到一组主机，统一策略、证据和响应台账

B  检测工程 / 紫队闭环
   规则生命周期、回放、覆盖率、误报治理、对抗验证

C  证据级审计 / 合规
   WORM、外部时间戳、证据链交接、可复核报告

D  团队协作 / RBAC / 加密
   多角色、多租户、静态加密、审批分离
```

推荐优先级：B > A > C > D。  
理由：检测工程最接近“真实防守”，也最容易用回放和覆盖率证明，不靠堆工具。

## 4.0 硬门槛

以下全部满足，才允许 4.0 立项：

```text
3.0.0 已发布
3.1.0 控制台已稳定
73 个工具契约全绿
至少 3 次真实授权演练，或 30 天影子 soak
无未关闭 P0
K1–K5 有外部证据，不只是单测
迁移/回滚在真实数据副本上演练通过
```

少一条都不立项。

## 4.0 非目标

```text
不做自主破坏性响应
不做常驻 EDR agent
不做 SaaS 多租户
不做“AI 自动攻击”
不为了版本号重写已经稳定的模块
```

## 4.0 的出口长什么样

不是“功能列表完成”，而是：

```text
能在一个真实防守周期里持续运行
能解释每一次阻断和放行
能复盘每一次漏报和误报
能在换一台主机后复现同样的结果
```

