# 4.0 构思：多主机协同防守

> 状态：概念稿，不立项、不开发、不排期；3.0 已发布（3.0.7），作者休息中  
> 复评：作者恢复维护后再评估，不设固定日期  
> 主主题候选：A 多主机 / 多目标持续防守  
> 支撑主题：B 检测工程 / 紫队闭环

## 一句话

3.0 是**单机防守工作台**；4.0 是**一张可编排的防守网络**。

```text
3.0：一台机器，一个网关，一个事实库
4.0：多台主机，统一策略，本地执行，集中证据
```

## 为什么不是 3.0 加工具

3.0 已经能：

```text
单机路径阻断
单机任务/审批
单机证据锚定
单机响应台账
```

但多主机场景下还缺：

```text
统一策略下发
主机身份与信任
策略版本/回滚
离线执行
跨主机证据关联
跨主机响应协调
主机失联/被控
```

这些不是“再加 7 个工具”能解决的，所以才是 4.0。

## 4.0 的“并联”是什么意思

不是串行代理链，而是：

```text
每台主机一个本地网关，各自执行
控制面统一发策略
证据面汇总不替代本地
单台失联不影响其他主机
```

逻辑拓扑：

```text
                control plane
        policy / inventory / rollout
                    |
      +-------------+-------------+
      |             |             |
  gateway-A     gateway-B     gateway-C
   host-A        host-B        host-C
      |             |             |
  local DB      local DB      local DB
      \             |             /
             evidence index
```

## 分层

### 控制面

```text
策略编译
策略签名
主机清单/范围
策略下发
版本/回滚
证据索引
```

控制面**不直接碰主机**，只发签名策略包。

### 数据面

```text
每台主机一个 gateway
本地策略缓存
本地执行
本地 SQLite
本地 timeline / anchor
断网继续执行
```

数据面必须能在控制面失联时独立工作。

### 证据面

```text
本地证据是源
中心只做索引/汇总
每台主机独立锚定
跨主机关联用 host_id + boot_id + seq
```

中心不是唯一真相源，避免控制面被攻破后证据全丢。

### 管理面

```text
主机列表
策略版本
下发状态
异常主机
跨主机案件
审批/响应
```

## 策略流

```text
1. 控制面编译策略
2. 计算 hash，签名
3. gateway 拉取/接收
4. 本地验签
5. 原子切换
6. 保留旧版本
7. 失败自动回滚
```

原则：

```text
签名不过不加载
hash 不对不加载
旧版本不删
离线用最后一份有效策略
```

## 信任与引导

最难的不是代码，是“主机怎么可信地加入”。

候选：

```text
一次性 join token
主机生成密钥对
CSR 换 mTLS 证书
控制面登记 host_id
证书短期有效 + 轮换
```

必须防：

```text
伪造主机加入
重放旧策略
控制面被控后下发恶意策略
主机证书泄漏
```

## 证据关联

单机 timeline 用 hash 链。  
多主机需要额外字段：

```text
host_id
boot_id
seq
wall_clock
monotonic_clock
policy_hash
```

跨主机时间不能只信墙钟。  
需要允许“时间有偏差”的关联，不假装全局严格顺序。

## 响应协调

3.0 的响应是单机台账。  
4.0 要回答：

```text
封一台还是封一组？
谁审批？
爆炸半径多大？
失败怎么回滚？
主机失联时谁执行？
```

默认仍然：

```text
高危动作人工审批
不自动执行破坏性命令
响应是台账 + 人工回填
```

## 失败模式

必须设计：

```text
控制面挂了
主机断网
策略包损坏
签名错误
旧策略回放
主机被控
证书泄漏
两台主机时钟差 5 分钟
策略下发一半失败
```

4.0 的验收不是“功能多”，是这些失败模式下仍然可解释。

## 分阶段

### 4.0-A 两台主机原型

```text
1 个控制面
2 个 gateway
mTLS
签名策略
离线继续
原子切换/回滚
```

出口：

```text
控制面停机，两台仍执行
断网重连后策略追平
错误策略拒绝加载
```

### 4.0-B 八台主机

```text
策略分批下发
失败重试
证据索引
主机列表/状态
回滚演练
```

出口：

```text
单台失败不影响其他
策略回滚 < 1 分钟
跨主机案件可追
```

### 4.0-C 长线测试

```text
6 个月
3 次真实授权演练
3.0 回退演练
混沌测试：断网/重启/证书过期
```

出口：

```text
无未解释跨主机绕过
证据可复核
回退可用
```

## 非目标

```text
不做 EDR 内核驱动
不做常驻提权 agent
不做自动破坏性响应
不做 SaaS 多租户
不做云厂商绑定
```

```text
3.0 policy engine 复用

3.0 工具/控制台尽量复用

4.0 不合并进 3.0
```
