# 3.0 行为契约与 M0 基线

> 状态：M0 已建立  
> 基线：2.0.0（`646a8ea`）  
> 用途：3.0 重写时判断“行为有没有漂移”，不是功能说明书。

## 1. 两类向量

```text
2.0 快照向量   必须与 2.0 行为完全一致
3.0 契约向量   3.0 必须满足；2.0 不保证
```

| 文件 | 类型 | 来源 | 3.0 要求 |
| --- | --- | --- | --- |
| `test/vectors/state.json` | 2.0 快照 | `lib/judge.js` | 逐条一致 |
| `test/vectors/timeline.json` | 2.0 快照 | `lib/store.js` | 逐字节一致 |
| `test/vectors/risk.json` | 2.0 快照 | `lib/plan.js` | 逐条一致 |
| `test/vectors/tools.json` | 2.0 快照 | `lib/tools.js` | 现有 66 个一致 |
| `test/fixtures/evidence-bundle.json` | 2.0 快照 | `lib/evidence.js` | 3.0 必须能验签 |
| `test/vectors/path.json` | 3.0 契约 | 设计文档 | 40 条全绿 |

## 2. state.json

内容：

```text
7 个状态
7 x 7 = 49 条迁移
每条 { from, to, allowed }
```

注意：

```text
同状态迁移 allowed=true
这是 2.0 canTransitionTask 的既有语义，不是新允许的边
```

3.0 要求：

```text
v3/domain/task/states.js 的 canTransitionTask 必须逐条一致
pending_approval -> dispatched 必须为 false
terminal -> 任何非自身状态必须为 false
```

## 3. timeline.json

公式必须逐字节一致：

```js
sha256(JSON.stringify([
  prevHash || '',
  engagement_id,
  at,
  actor,
  action,
  target,
  detail,
]))
```

向量是 3 条链：

```text
第 1 条 prev_hash = ""
第 2 条 prev_hash = 第 1 条 hash
第 3 条 prev_hash = 第 2 条 hash
```

3.0 要求：

```text
v3/domain/evidence/hash.js 输出与 expected_hash 完全一致
不允许改 JSON.stringify 的数组格式
不允许把 null 和 "" 混用
```

## 4. risk.json

10 条用例，覆盖：

```text
ir + 隔离 => high/pending_approval
ir + 查日志 => medium/queued
hardening + 改防火墙 => high
hardening + 检查防火墙 => medium
monitor/hunt/intel 普通任务 => low
显式 high 不能降级
ir + 隔离 + 显式 low 仍为 high
```

3.0 要求：

```text
v3/domain/task/risk.js 与 2.0 逐条一致
3.0.0 不允许“顺手优化”正则
```

## 5. tools.json

内容：

```text
66 个工具
name
parameters（完整 JSON Schema）
output_schema（只保留 type）
7 个角色的工具数
```

不冻结：

```text
description
execute 实现
工具注册顺序
```

3.0 要求：

```text
现有 66 个名称/参数/输出 schema 不变
新增的 7 个工具另算，不覆盖旧名字
角色白名单现有 66 个计数不变
```

## 6. path.json

这是 3.0 的对抗契约，不是 2.0 行为快照。

40 条覆盖：

```text
保护前缀、边界、大小写
点段、编码分隔符、双重编码
控制字符、反斜杠、分号、尾随点/空格
absolute-form、fragment、空路径、非 origin-form
deny 规则、allow 规则、默认放行
```

判定顺序：

```text
deny
-> protected allow
-> protected block
-> default_action
```

每条结构：

```json
{
  "id": "p01",
  "input": "/admin",
  "expect": {
    "decision": "block",
    "canonical": "/admin",
    "reason": "PROTECTED_PREFIX"
  }
}
```

3.0 要求：

```text
M3 的 normalize + policy 必须让 40 条全部通过
allow 必须有 canonical
block 的 canonical 可以为 null，但 reason 必须明确
```

2.0 差异：

```text
2.0 只检查 %2e/%2f、点段、//、NUL
2.0 不检查 %5c、absolute-form、fragment、尾随点/空格
所以 path.json 不能拿去要求 2.0 通过
```

## 7. evidence-bundle.json

由 2.0 `buildEvidenceBundle` 生成，包含：

```text
schema: dsh-blue-evidence/v1
canonical JSON + sha256 digest
Ed25519 signature
public_key + key_id
timeline 完整性
```

3.0 要求：

```text
verifyEvidenceBundle(fixture).ok === true
schema 不变
digest 算法不变
旧包可验签
```

限制：

```text
fixture 的 generated_at 是生成时的时间
重新生成会改变 digest/signature
只在有意更新 fixture 时重新生成
```


注意：

```text
state/risk/path/tools 是确定性的
timeline 是确定性的
evidence 含 generated_at，每次重生成都会变
```

## 10. 变更规则

```text
1. 不允许为了让测试通过而改 expected
2. 2.0 快照向量只在 2.0 行为有意变化时重生成
3. path.json 改动必须先改 docs/3.0/design.md
4. tools.json 只在工具契约变化时重生成
5. evidence fixture 只在 schema/签名算法变化时重生成
```
