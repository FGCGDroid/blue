# 3.0 用户定位（必须遵守）

## 目标用户

```text
有服务器 / 有网站 / 有小团队
但不会做安全防御的人
```

他们不是：

```text
CTF 专业选手
SOC 分析师
会写 Sigma/YARA/Suricata 规则的人
会自己接 ELK/EDR/流量的人
```

## 他们真正要的

```text
1. 装上就能用
2. 不用懂 ATT&CK、CVE、Sigma
3. 不用自己起网关、接日志、写规则
4. 一句话告诉我：现在有没有危险
5. 有危险时告诉我先做什么，不要甩 74 个工具
6. 默认不乱封、不乱删、不乱改
7. 出事能导出报告和证据
```

## 3.0 的产品底线

```text
默认路径必须是一条龙：
安装 -> 选“保护我的服务器” -> 填 IP/域名 -> 自动盘点
-> 自动接能接的日志 -> 出人话结论 -> 只让用户做选择题
```

不能把下面这些东西丢给目标用户：

```text
blue_range / ctf_lab / Sigma 规则 DSL
gateway 端口 / policy hash / OTLP
ATT&CK 覆盖矩阵 / 证据 schema
```

这些是高级功能，必须收进“高级模式”。

## 当前差距

```text
2.0：一条龙体验相对完整，但能力浅
3.0：能力强，但把复杂度暴露给用户
```

3.0 只有满足下面三条，才算对目标用户有价值：

```text
1. 一个“保护我的服务器”向导
2. 自动采集/接入日志，不让用户配管道
3. 首页只显示：安全 / 有风险 / 需要你确认
```

## 开发取舍

优先级：

```text
P0 向导、自动接入、人话结论
P1 常用加固、告警解释、一键报告
P2 多目标、团队、审批流
P3 CTF 适配器、ATT&CK 覆盖、专业规则
```

不做的方向：

```text
不把“工具数量”当卖点
不把 CTF 靶场适配当主功能
不要求用户先学会蓝队术语
不让用户手工拼命令才能开始
```

## 一句话

```text
3.0 是给“有服务器但不会防御的人”用的，
不是给会打 CTF 的人炫技用的。
```

## 方便优先（硬规则）

同一个功能，如果有两种做法：

```text
A. 让用户记 URL、命令、参数、工具名
B. 让用户点一下、填一个框、说一句话
```

永远选 B。

具体：

```text
能点按钮就不让用户记 URL
能一个输入框就不拆成五个字段
能默认值就不让用户选
能一句话说清就不显示 JSON
能自动发现就不让用户填路径
出错用中文说人话，不甩错误码
```

专业能力可以保留，但必须藏在“高级模式”，不能挡在默认路径上。

判断标准：

```text
用户从安装到看到“正在保护”，最多几步？
超过三步，就是设计失败。
```
