# 应急响应（PICERL）

## Preparation（准备）
- 资产清单、联系人、隔离手段（EDR 隔离 / 交换机 ACL / 安全组 / 关机）是否可用。
- 取证工具与存储是否就绪；时间同步。
- 明确“谁有权批准隔离/下线”，避免临场扯皮。

## Identification（识别）
1. 事实：什么时间、哪台资产、什么现象、谁发现的、影响哪些服务。
2. 证据：告警原文、日志、进程/网络连接、文件、账号登录。
3. 范围：单机 / 同网段 / 同账号 / 同入口；是否已横向。
4. 定级：
   - P0：Flag/核心服务/域控/数据库失陷，攻击者正在横向
   - P1：单机失陷、WebShell、凭据泄露
   - P2：可疑但未确认
`blue_alert_triage` + `blue_timeline` 落库。

## Containment（遏制）
优先顺序：
1. 阻断横向：隔离主机、封 SMB/RDP/WinRM/SSH 来源、禁用被盗账号。
2. 阻断外连：封 C2 IP/域名、下掉隧道、限制出站。
3. 保住证据：隔离前尽量采集内存、进程树、网络连接、关键日志。
4. 不要直接重装/删除——先确认证据已保全。

隔离方式对比：
| 方式 | 影响 | 适用 |
| --- | --- | --- |
| EDR 网络隔离 | 保留主机运行与内存 | 首选 |
| 交换机 ACL/安全组 | 断网但主机仍运行 | 无 EDR |
| 关机 | 丢失内存，攻击者可能反制 | 最后手段 |

## Eradication（清除）
- 删除 WebShell/恶意服务/计划任务/启动项/隐藏账号/SSH key。
- 修复入口：上传校验、组件升级、弱口令、未授权接口。
- 轮换该主机上所有凭据、Token、数据库密码、API Key。
- 每清一项立刻复验（文件是否再生、进程是否重启、连接是否重连）。

## Recovery（恢复）
- 从干净备份恢复；先核心服务，再边缘。
- 恢复后复测：服务可用、IOC 不再命中、入口漏洞已修复、日志有监控。
- 观察 24–72 小时异常。

## Lessons Learned（复盘）
- 时间线（UTC）、根因、影响、处置动作、仍缺失的检测。
- 更新 `blue_finding_add` / `blue_ioc_add` / 检测规则。
- `blue_report write=true` 输出报告。

## 红线
- 不删除原始证据；不运行未知样本；不向业务写入测试数据。
- 破坏性操作（重装、格式化、批量杀进程）先经指挥官/用户确认。
